## 프로젝트 소개

Campus Planner는 대학생이 수업·팀프로젝트·자격증 학습 일정을 한곳에 등록하고 관리하는 웹서비스를 가정한 예시 프로젝트입니다. 사용자는 일정의 마감일과 진행 상태를 확인하고, 완료한 학습 활동을 기록할 수 있습니다.

- 프로젝트 유형: 팀프로젝트(예시)
- 개발 기간: YYYY.MM ~ YYYY.MM(본인 프로젝트의 실제 기간으로 교체)
- 저장소: 본인의 GitHub Repository URL을 입력
- 시연 URL: 실제 배포 주소가 있다면 입력하고, 없다면 생략

## 개발 목적

팀프로젝트 일정과 개인 학습 일정을 여러 앱에 나누어 기록하면 마감일을 놓치기 쉽습니다. 이를 해결하기 위해 일정의 생성부터 완료 처리까지 한 화면에서 관리하도록 설계했다고 가정합니다. 이 예시의 학습 목표는 REST API 설계, 데이터베이스 모델링, 프론트엔드 상태 관리, 예외 처리 경험을 문서로 설명하는 것입니다.

## 주요 기능

| 기능 | 설명 | 관련 API(예시) |
| --- | --- | --- |
| 일정 목록 | 마감일순 일정 조회와 진행 상태 필터 | GET /api/schedules |
| 일정 등록 | 제목·마감일·분류를 입력하여 등록 | POST /api/schedules |
| 일정 수정 | 기존 일정의 내용과 마감일 수정 | PUT /api/schedules/{id} |
| 완료 처리 | 진행 중인 일정을 완료로 변경 | PATCH /api/schedules/{id}/complete |
| 입력 검증 | 빈 제목·잘못된 날짜 입력에 대한 오류 표시 | 400 Bad Request |

실제 구현하지 않은 기능은 적지 마세요. 로그인, 알림, AI 추천 등은 구현한 경우에만 추가하세요.

## 기술 스택

| 구분 | 기술(예시) | 선택 이유 |
| --- | --- | --- |
| Backend | Java 17, Spring Boot 4, Spring Web, Spring Data JPA | REST API와 데이터 접근 계층 구현 |
| Database | H2(로컬 개발용) | 별도 DB 서버 없이 빠르게 기능 검증 |
| Frontend | Vue 3, Vite, JavaScript | 컴포넌트 기반 UI 및 빠른 개발 |
| 협업 | Git, GitHub | 이슈·브랜치·Pull Request 이력 관리 |
| 검증 | JUnit 5 | 서비스 로직과 API 동작 테스트 |

버전·라이브러리·도구는 실제 프로젝트의 build.gradle, package.json에 맞춰 기재하세요.

## 시스템 구조

예시 구조는 브라우저의 Vue 화면에서 Spring Boot REST API를 호출하고, 서버가 JPA를 통해 H2 데이터베이스에 접근하는 3계층 구조입니다.

~~~text
[사용자 브라우저]
       |
       v
[Vue 3 / Vite]
       | HTTP/JSON
       v
[Spring Boot REST Controller]
       |
       v
[Service / Repository (JPA)]
       |
       v
[H2 Database]
~~~

예시 폴더 구성:

~~~text
campus-planner/
├── backend/        # Spring Boot 프로젝트
├── frontend/       # Vue 프로젝트
├── docs/           # 설계 문서, 화면 캡처
└── README.md       # 현재 문서
~~~

가능하다면 실제 ERD, 데이터 흐름, 배포 구조와 주요 컴포넌트 간 관계도도 추가하세요.

## 설치 및 실행

다음은 위 폴더 구조를 갖춘 프로젝트를 가정한 **명령어 예시**입니다. 실제 Repository의 실행 명령, 운영체제별 차이 및 필수 환경변수를 확인한 뒤 고쳐 쓰세요.

필수 환경: JDK 17 이상(프로젝트 설정과 호환되는 버전), Node.js(프로젝트가 요구하는 버전), Git.

~~~bash
# 1. 본인 GitHub 주소로 교체하여 프로젝트 받기
git clone https://github.com/YOUR-ID/campus-planner.git
cd campus-planner

# 2. 백엔드 실행 (macOS/Linux)
cd backend
./gradlew bootRun
# Windows: gradlew.bat bootRun

# 3. 다른 터미널에서 프론트엔드 실행
cd frontend
npm install
npm run dev
~~~

- 백엔드 예시 주소: http://localhost:8080
- 프론트엔드 예시 주소: http://localhost:5173
- H2 접속 설정 및 CORS 허용 주소는 실제 프로젝트 설정값을 문서에 추가
- 데이터베이스 계정, 토큰, 비밀번호가 필요한 프로젝트는 **값이 없는 환경변수 목록**만 설명하고 비밀 값은 GitHub에 올리지 않기

## 트러블슈팅

**문제(예시):** 프론트엔드 개발 서버에서 백엔드 API를 호출했을 때 브라우저가 CORS 오류를 표시했습니다.

**원인 분석(예시):** 프론트엔드 개발 주소와 백엔드 API 주소의 출처가 달랐고, 서버의 허용 출처 설정을 확인할 필요가 있었습니다. 브라우저 개발자 도구에서 요청의 Origin과 응답 헤더를 점검했습니다.

**해결 과정(예시):** 개발 환경에서 필요한 프론트엔드 출처만 허용하도록 서버 CORS 정책을 구성했습니다. 모든 출처를 무조건 허용하는 대신 환경에 따라 허용 주소를 분리했습니다.

**검증 방법(예시):** 개발자 도구의 Network 탭에서 사전 요청 및 실제 API 응답을 확인하고, 정상·오류 응답을 모두 테스트했습니다.

실제 프로젝트의 오류 로그, 재현 절차, 수정 전후 차이, 테스트 결과를 근거로 작성하세요. 위 사례는 작성 형식 참고용이며 실제 해결 이력이 아닙니다.
